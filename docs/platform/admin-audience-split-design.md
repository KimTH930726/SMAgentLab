# 관리자 화면을 보는 사람별로 나누기 — 컬렉션 관리(시니어) / 플랫폼 관리(관리자) (2026-11-03 — 검수 승인, 2·3단계 구현 v2.205)

> 상태: **현행 — v2.205(11/03)에 구현**(아래는 설계 근거). 계기(태훈 11/03): "운영 시니어급 관리자가 관리해야 하는 데이터 품질 화면(시스템별로)과,
> 나 같은 관리자가 보는 공통 게이트·AI 감사 로그·OpsLens 자체 최적화 화면을 잘 나눠서 보여 줘야 한다." 같은 날 결정한 M2
> (정정은 **근거가 속한 컬렉션의 담당**에게 간다)가 이 나누기의 첫 사용처다. 앞선 구조: [admin-ia-design.md](../archive/admin-ia-design.md)(도메인 경계대로 5묶음).

## 1. 지금 막힌 일

| 막힌 일 | 지금 모습 | 왜 문제 |
|---|---|---|
| 시스템 시니어가 "내 시스템 지식 상태"를 한눈에 못 본다 | 운영 지식·정정 요청·통계·소스 연결이 서로 다른 묶음(지식 / 품질)에 흩어져 있고, 품질 묶음엔 관리자 전용(AI 감사 로그·사용자 피드백)이 섞임 | 할 일(승인 대기·적재 검토·정정·지식 공백)을 찾으려면 메뉴 4~5개를 돌아야 한다 → 안 쓰게 된다 |
| 연결된 컬렉션 근거의 정정이 주인에게 안 간다(M2) | 정책 컬렉션에서 물어 시스템 지식으로 답한 [답변 틀림]은 물은 컬렉션 큐로만 가고, 그 근거는 후보에서 빠진다 | 시스템 시니어는 자기 지식이 틀렸다는 신호를 못 받는다 |
| 관리자의 "OpsLens 자체를 보는 화면"이 한데 없다 | 평가 게이트(품질) · AI 감사 로그(품질) · LLM 사용량(설정 안) · 조직·권한 · 캐시(시스템·권한)가 따로 | 플랫폼이 잘 돌고 있나(정확도·AI 판단·비용)를 아침에 한 번에 못 본다 |
| 메뉴가 보는 사람과 무관하게 같다 | 일반 사용자는 관리자 전용 몇 개만 빠진 같은 트리 | 시니어에게 필요 없는 메뉴가 많고, 관리자에게는 컬렉션별 화면이 반복된다 |

## 2. 업계 조사 (우리 규모에 맞는 것만)

| 도구 | 나누는 방식 | 가져오는 것 | 안 가져오는 것 |
|---|---|---|---|
| Confluence | **사이트 관리**(사용자·그룹·전역 설정) vs **스페이스 관리**(그 스페이스 설정·권한·내용) — 범위로 나눔 | 플랫폼 관리 / 컬렉션 관리 두 범위. 컬렉션 담당은 자기 컬렉션만 | 스페이스별 권한 세부 설정(우리는 담당 파트 하나로 충분) |
| Zendesk Guide | 문서 **소유자(사람 또는 그룹)** + 관리자가 정한 **검증 주기** → 기한 지나면 소유자에게 알림·검증 목록 | 정정·검증 신호는 **콘텐츠 소유자**에게 라우팅(M2와 같음) | 검증 주기·알림 메일(아래 §5) |
| Grafana / Datadog | 조직 관리자 vs 팀 관리자. Datadog은 팀을 **필터용 소유 표시**로 쓰고 접근 제어와 분리 | 시니어 화면 = 담당 컬렉션 **필터가 기본**, 다른 컬렉션은 조회만(우리 10/21 결정과 같음) | 팀별 대시보드 편집 권한 |

## 3. 하는 것 (MVP)

```
관리자 화면 — 왼쪽 위에 범위 전환 [컬렉션 관리 | 플랫폼 관리](플랫폼 관리는 관리자만 보임)

컬렉션 관리 (시니어 · 담당 파트 사람)  — 컬렉션 고르기: 내 담당이 맨 위, 시스템 먼저 · 다른 컬렉션은 조회만
├ 홈               카드 = 큰 숫자 1개 + [자세히]: 정정 요청 · 승인 대기 · 적재 검토 · 지식 공백 · 중복 의심 · (정책) 검토 대기
├ 운영 지식         조회 · 등록 · 적재 검토 · 승인 대기 (시스템 컬렉션)          ← 지식 › 운영 지식
├ 정책서            정책 · 참고표 · 개요 (정책 컬렉션)                             ← 지식 › 정책서
├ 정정 요청         근거가 이 컬렉션 것인 정정(M2) — 승인 · 직접 수정 · 반려       ← 품질 › 정정 요청
├ 용어집            이 컬렉션 용어                                                 ← 지식 › 용어집
├ 통계              이 컬렉션 질의 · 지식 공백                                     ← 품질 › 통계
├ 소스 연결         이 컬렉션으로 들어오는 컨플 공간 · 동기화 이력                 ← 지식 › 소스 연결
└ 컬렉션 정보       담당 파트 · 관련 정책/시스템 · 코드(읽기, 수정은 관리자)        ← 컬렉션 › 정책/시스템 컬렉션의 그 줄

플랫폼 관리 (관리자)
├ 홈               카드: 정답률(업무지식·정책서) · 단정 오답 · AI 판단 바꾼 비율 · LLM 호출 · 피드백 미처리 · 담당 없는 컬렉션
├ 평가 게이트       리포트 · 기법 대장 · 자가 개선 · 판정 이력                      ← 품질 › 평가 게이트
├ AI 감사 로그      AI가 정한 것(등록 위치·되묻기·원문 확인·컬렉션 제안) · 사람이 바꿨나 ← 품질 › AI 감사 로그
├ 사용자 피드백     오류 신고 · 기능 제안 · 자동 감지                                ← 품질 › 사용자 피드백
├ 컬렉션            정책 / 시스템 목록 · 만들기 · 관련 정책 연결 · 코드              ← 컬렉션 › 정책·시스템 컬렉션
├ 조직·권한         사용자 · 팀›파트 · 담당 컬렉션                                    ← 시스템·권한 › 조직·권한
├ VOC 이메일        메일함·분석(정책 컬렉션 기준, 후순위)                             ← VOC 이메일
└ 설정              LLM · 프롬프트 · 검색 기준값 · 메뉴 노출 · LLM 사용량 · 캐시       ← 시스템·권한 › 설정 · 캐시
```

- **화면 내용은 그대로 옮긴다**(1단계는 자리만 — admin-ia-design §5-2 방식). 새로 만드는 건 두 홈의 카드뿐이고, 숫자는 지금 API를 재사용한다
  (통계 · 정정 대기 수 · 적재 검토 수 · 평가 게이트 최신 기록 · AI 감사 로그 요약 · LLM 사용량 · 피드백 수). 새 집계가 필요한 카드는
  "중복 의심" 하나(check_ingest의 중복 검사를 컬렉션별로) — 없으면 1단계에서 뺀다.
- **옛 주소 유지**: `/admin/<id>`는 그대로 두고 새 묶음 안에서 같은 화면을 연다(옛 링크·E2E가 안 깨지게).
- **일반 사용자**: 범위 전환이 안 보이고 컬렉션 관리만. 조회 전용은 지금처럼 설정 등 일부만.

### 권한 규칙 (바꾸지 않음 — 화면만 나눈다)

| 범위 | 보기 | 쓰기·승인 |
|---|---|---|
| 컬렉션 관리 | 로그인 사용자 누구나, 모든 컬렉션(10/21 결정: 다른 파트 지식도 조회) | 그 컬렉션 **담당 파트** + 관리자. 담당 없는 컬렉션은 관리자만 |
| 관련 정책 연결 | — | 권한을 **넘기지 않는다**. 회원(정책) 담당이 홈페이지 시스템 지식을 고치려면 홈페이지 시스템 담당이어야 함 |
| 정정 요청(M2) | 근거가 속한 컬렉션 큐 | 그 컬렉션 담당. 근거가 정해지기 전(대상 미정)은 물은 컬렉션 큐에 "다른 컬렉션 근거 포함" 표시 → 대상이 정해지면 그 컬렉션 큐로 옮김 |
| 플랫폼 관리 | 관리자만 | 관리자만 |

## 5. 안 하는 것 + 다시 볼 조건

- **"시니어" 역할 따로 만들기** — 지금은 담당 파트 사람이 곧 시니어(권한은 컬렉션 단위). 다시 볼 조건: 파트 안에서 등록하는 사람과
  승인하는 사람을 나눠야 할 때(정책 v0 설계의 "나중엔 시니어급만 승인"과 같이).
- **검증 주기·만료 알림**(Zendesk 방식) — 지식 수가 적고 낡음 신호가 아직 없다. 다시 볼 조건: 정정 요청에 "옛 내용" 사유가 쌓이거나
  시스템 지식이 수천 건을 넘을 때.
- **메일·Teams 알림** — 홈 카드로 먼저. 다시 볼 조건: 카드를 안 보고 정정이 쌓이는 일이 실제로 생길 때.
- **커스텀 역할·컬렉션별 세부 권한** — 팀 하나 · 시스템 5개 규모에선 과설계.
- **시니어 홈 카드 편집(위젯 고르기)** — 카드 6개 고정.

## 6. 순서 (단계마다 검수)

1. 이 문서 + 화면 모양(목업) 검수.
2. 메뉴 재배치(자리만) + 범위 전환 + 옛 주소 유지 — E2E(메뉴·주소) 갱신.
3. 두 홈 카드(기존 API 숫자).
4. M2 정정 라우팅을 컬렉션 관리 › 정정 요청에 연결(백엔드는 따로 진행 중).

## 7. 검수받을 것

1. 범위 이름 **컬렉션 관리 / 플랫폼 관리** 가 맞는지(대안: 운영 콘솔 / 관리 콘솔)
2. VOC 이메일을 플랫폼 관리로 둘지
3. 시스템 정보(준비 중) 메뉴를 내릴지
4. 시니어 홈 카드 6개 구성
5. 정정 대상이 정해지기 전 신고를 물은 컬렉션 큐에 두는 규칙
