# 골든셋 재생성 절차 — 재정제 전후 품질을 같은 기준으로 재기 위해 (2026-09-28)

> **왜 필요한가**: 지금 골든셋(`backend/tests/fixtures/golden_set/online_delivus_v1.jsonl`, 89문항)은
> 현재 적재된 정책서 두 파일에서 뽑은 질문이다. 데이터를 재정제해 다시 넣으면 **정답 위치(파일/시트/
> 행)가 바뀌어** 옛 골든셋으로는 채점이 조용히 틀어진다 — 2026-09-28에 실제로 평가 스크립트가
> 네임스페이스를 잘못 골라 "지식 없음 39%"라는 틀린 수치를 만든 적이 있다(실제 12%). 이 문서는
> 그런 일이 재정제 시점에 반복되지 않게 하는 체크리스트다. 골든셋 **포맷 스펙**은
> `docs/policy-doc-pipeline-plan.md` §4-1이 원본 — 여기선 재생성 절차와 함정만 다룬다.

---

## 1. 재정제 **전** — 기준선을 남긴다

재정제 후 "좋아졌나"를 말하려면 재정제 전 수치가 있어야 한다. 옛 데이터가 DB에 남아 있을 때 한 번:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml exec backend \
  python scripts/diagnose_no_knowledge.py --skip-logs      # A/B/B-rank/C/D 분류 (문항별 네임스페이스)
```

결과(특히 **D 정상 비율**, 2026-09-28 기준 75/89 = 84.3%, 정책 top_k=10)를 이 문서 §5에 기록한다.
LLM 답변은 실행마다 흔들리므로(가드 평가에서 OFF끼리도 35~37/89) 한 번 값이 아니라 **2회 실행**해
범위로 적는다.

## 2. 재정제 **후** — 골든셋을 새로 만든다

1. **새 원본 파일로 임포트** (`POST /api/policy/import`). 파이프라인을 바꿨다면 `reprocess_all=true`
   (v2.114) — 안 그러면 내용이 같은 행은 스킵된다.
2. **질문 작성** — §4-1 스펙 그대로(JSONL, 유형 4종, 유형별 10~15개). **원문 문구를 베끼지 않는다**
   (검색이 너무 쉬워져 점수가 부풀려짐).
3. **`source`는 새 파일 기준으로** — `param`/`narrative`는 새 파일의 시트명·행번호, `navigation`은
   새 카테고리명, `condition_filter`는 새 조건 문자열. 재정제로 행 순서가 바뀌면 옛 `row` 값은
   **전부 무효**다.
4. **새 파일명이 네임스페이스 매핑에 걸리는지 확인** — `service/policy/track2.py`의
   `_FILE_TO_NAMESPACE`는 파일명에 "온라인스토어"/"딜리버스"가 **포함**돼야 매핑된다. 파일명이
   바뀌면 여기에 추가한다. 안 맞으면 그 문항은 채점에서 빠진다(v2.114부터 경고 로그로 드러남:
   `[골든셋] N문항 중 M문항만 채점 대상 — 제외 사유: ...`).
5. **파일명은 버전을 올린다** (`online_delivus_v2.jsonl` 등) — 옛 파일은 기준선 재현용으로 남긴다.
   경로는 `track2._GOLDEN_SET_PATH`.

## 3. 채점 전 확인 — 분모가 줄지 않았는지

- `diagnose_no_knowledge.py` 출력 첫 줄의 **문항 수**가 JSONL 줄 수와 같은지 본다. 다르면 경고 로그의
  제외 사유부터 해결한다. 분모가 줄어든 채 비율만 보면 "정확도가 올랐다"로 오독한다.
- 가드/프롬프트 변경을 잴 땐 `scripts/eval_prompt_guard.py`(OFF/ON 같은 컨텍스트 비교) — 이것도
  문항별 네임스페이스를 쓴다(v2.112 수정).

## 4. 정책 외 축 (컨플루언스·DB 스키마 등)

지금 로더(`track2._load_golden_set`)는 **정책서 전용**이다 — `source`를 정책 파일/시트/행으로만
해석한다(`project_common_platform_roadmap` 메모리의 L6 경계: 사례 1개로 범용 로더를 미리 만들지
않는다). 다른 축의 골든셋이 필요해지면 **그 축 전용 로더를 새로 짜고** 채점 로직(`hit@K`/Top-1 등,
축 무관 순수 함수)은 재사용한다. 컨플루언스는 v2.115부터 행에 `confluence_page_id`가 남으므로
`source: {"confluence_page_id": ...}`로 정답을 지정할 수 있다.
