### 4-2. 참고표 — 새 테이블
- `ref_table`: id, logical_id, version, namespace_id(정책 파트), title, source_section(소속 절), columns(열 이름 + 역할 조건/결과),
  status, content_hash.
- `ref_table_row`: ref_table_id(버전), row_no, cells(jsonb).
- 파생: 압축본(결정 열 기준, 저장 시 계산), 표 요약 1개(임베딩 — 표 단위 검색용).
- 저장 검사: 열 구성 일치 · 조건 조합 중복 0 · **같은 결정 조건 → 다른 결과 = 모순(저장 거부)** · 압축본을 펼치면 원표와 같음.
- 작은 표 3개(2,900자 이하)는 압축 없이 통째.

### 4-3. 공간·연결
- 정책 파트 14개 = `ops_namespace`(종류 표시: 정책/업무), 소유 `owner_part_id`는 지금 미지정(슈퍼어드민 승인).
- `ops_link`(신규, 범용): (from_type, from_id) —relation→ (to_type, to_id), source(사람/자동), status. id는 버전 불변 logical_id.
  지금 쓰는 관계: 정책 파트 ↔ 업무 파트 "같은 업무", 참고표 → 소속 절·정책 "참조". 나중: 용어 ↔ 용어 "같은 개념", 소스 연결(온톨로지).

**관계도** ([기존] = 지금 DB, [신규] = v0에서 추가)
```
ops_part[기존] ─owner_part_id→ ops_namespace[기존 + 종류 칸: 정책/업무]  ← 모든 데이터가 namespace_id로 하나에 소속(권한 상속)
  ├ policy_item[기존] ─ policy_chunk(1, 파생) · policy_param(N, 파생) · policy_review_log   (supersedes_id로 버전)
  ├ ref_table[신규] ─ ref_table_row[신규](원표)   (압축본·표 요약은 계산)
  ├ rag_source_document[기존](원문 원장) ─ rag_knowledge[기존] ─ history · duplicate_match · category
  ├ rag_glossary[기존] ─ rag_glossary_synonym
  └ ops_improvement_item[기존](정정·수정 제안 — target_type+target_id로 가리킴)
ops_link[신규]: (from_type, from_id) —relation→ (to_type, to_id) — 파트↔파트 같은 업무, 참고표→정책 참조, 정책→정책 참조,
                나중 용어↔용어 같은 개념·값→외부 시스템(온톨로지). id는 logical_id(버전 불변).
```
- 소속·구성은 외래키, 관계만 (종류, id) — 관계 종류마다 테이블을 늘리지 않으려고(정정 원장과 같은 패턴). 대신 DB가 대상 존재를 보장

## 7. 관리자 페이지

**메뉴 구조(10/20 확정, B안)** — 지금은 정책 파트 14개가 업무 파트와 구분 없이 기준정보·지식베이스·용어집 목록에 섞여 쓰기 어렵다.

```

```
순서: 백엔드 수정(채팅이 v0으로 답하게) 뒤 관리자 1단계와 묶어 진행.

원칙: **관리 체계는 하나**(수정 제안 → 승인 → 새 버전 → 재검사, 권한·감사·폐기 공통 — 대상은 (종류, id)), **저장·편집은 종류별**.

| | 정책 | 참고표 |
|---|---|---|
| 편집 | 텍스트 편집기 | 표 편집기 + 표 단위 CSV 내려받기·올리기 |
| 버전 | 정책 1건 | 표 1개 전체 |
| 검토 화면 | 원문 중심, 파라미터는 원문 하이라이트(원문에 없는 값 빨강) | 바뀐 행·칸 강조, 압축본 변화 |
| 조회 | 문서 > 장 > 절 트리 | 같은 트리에 표 아이콘, 기본 압축본 보기 + 원표 탭 |

- 1단계: 찾기·상세·버전 이력 + 원문 중심 검토 화면(옛 서술/파라미터 검토 화면 교체 — 검수 어려움) + JSON 가져오기(관리자 전용, 문서 개정본용).

- 3단계: 시행일·종료일, 변경 후 재검사.

- 서술 청킹·규칙 구간 조각: 득 없음(§3-1). 정책이 아주 길어 1위가 떨어지는 사례가 나오면 다시.
- 참고표 행 단위 검색, 추가 합성 실험: 상한 확인(§3-2). 실제 질문에서 표 찾기 자체가 틀리면 다시.
- 용어 간 연결·온톨로지·본문 언급 기반 연결 자동 제안: 연결 테이블만 준비. 사례가 쌓이면.
- 파트 소유자·권한 지정: 조사 후. 시행일: 실제 사례가 나오면.
