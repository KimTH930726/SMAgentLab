## 1. 지금 막힌 일
- 평가 게이트는 **골든셋(합성·사람 문항) 기준**만 잰다 — 실사용 질의가 잘 답해졌는지는 신고가 없으면 모른다.
- 지식(컨플) 정답 문항은 골든셋 측정·판정 기록에 연결이 안 됨 — 정답이 정책인 것만 판정 기록·리포트에 들어간다.
- 실사용 질의를 골든셋으로 올리는 길이 신고→정정 승인(자동)·검색 미리보기(관리자)뿐 — 질의 목록에서 바로 고르는 길이 없다.

## 2. 업계 → 우리
| 사례 | 요지 | 우리 |
|---|---|---|
| Langfuse 온라인 평가 | 운영 기록에 규칙(거르기 + **표본 비율** + LLM 채점기), 점수 추세를 대시보드로 | ③ 표본 채점 · 운영 숫자 |
| Ragas·TruLens·DeepEval(정답 없는 지표) | 충실도(근거에 없는 말?) · 답 적합성 · 문맥 관련성 — 질문·근거·답만으로 | ③ 판정 칸: 질문 모호 / 검색 / 생성 / 정상 |
| 업계 공통 주의 | 답 지표만 보면 검색이 나빠진 걸 놓친다 — 검색 지표 하나 + 답 지표 하나 | ② 검색 신호(근거 약함·근거 없음) + ③ |
| LangSmith 데이터셋·주석 큐 | 운영 기록에서 골라 데이터셋에 추가 · 검토 큐에서 고쳐 추가 · 조건 규칙으로 자동 추가 | ④ [골든셋에 추가] · 정정 승인 자동 |

## 3. 하는 것(MVP)
**이름(사용자 10/28 — 업계 용어로)**: 문항 모음 = **골든셋**, 넣는 동작 = **[골든셋에 추가]**(지금 화면의 "시험지에 넣기"), 질문 하나를 채팅과 같은 검색으로 펼쳐 보는 창 = **[AI 분석]**(지금의 "AI가 본 근거").
기존 화면 문구도 개발 때 같이 바꾼다(정정 요청 카드 · 지식 상세 · 평가 게이트).

1. **기록(trace, v2.187 완료)** — 답마다 넘긴 근거 id·순위·점수 + 판정 신호(원문 없음). 오류·중단 답에도 남음.
2. **질의별 진단(LLM 0, 전부)** — 근거 약함(최고 점수 < 기준) · 근거 없음 · 되묻기(→ 무엇을 골랐나) · 같은 대화 재질문 · 신고됨. 주 단위, 컬렉션별, 지난 4주 평균과 비교.
3. **표본 채점(주 30건 남짓, 로컬 LLM)** — 질문 + 그때 넘긴 근거(기록 id로 다시 꺼냄) + 답 → 질문 모호 / 검색 / 생성 / 정상. 컨플 원문이라 **로컬 LLM만**.
   - **채점기 보정 30건(사용자: "LLM이 만드는 걸로")** — 판정 라벨도 LLM이 만든다. 같은 모델이 라벨·채점을 다 하면 자기 실수를 못 잡으므로
     **라벨 = 다른 모델(또는 다른 지시문·더 큰 로컬 모델), 채점 = 운영 채점기**로 두고 일치도(카파)를 잰다. 컨플 원문은 게이트웨이 금지 → 라벨도 로컬 계열 안에서 갈라 쓴다.
     일치도가 낮으면 사람 판정 몇 건으로 보정(그때 다시).
4. **[운영 질의] 탭 + 단계별 운영 숫자(목업)** — 평가 게이트 단계 칸에 "틀림 n(골든셋) · 운영 n(지난 7일)", 탭은 카드 4장(질의 수 · 근거 없음 · 신고율 · 표본 채점) + 문제 질의 목록
   (진단 꼬리표 · 채점 결과 · [AI 분석 ▸] · [골든셋에 추가] · [정정 요청 ▸]). 질문 글은 관리자만. [AI 분석]은 그때 기록과 지금 다시 검색한 결과를 나란히.
5. **지식(컨플) 축** — 평가 게이트 맨 위 [정책서 | 지식(컨플)], 판정 기록에 축 칸(`eval_gate_run.axis`, 축마다 기준선). 지식 골든셋 =
   지금 합성 문항 106개(로컬 LLM 생성, 딜리버스 14 · 제휴서비스 92) + 실사용에서 [골든셋에 추가]한 지식 정답 문항(잠근 칸).
   기준선(10/28): 정답 지식을 AI에게 넘김 **95.3%**(101/106) · 상위 10 안 100% · MRR 0.85 · 답 정답률 측정 중.
   - 측정 스크립트가 문항의 옛 컬렉션 이름에 묶여 0%가 나왔다(10/2x 영역 재구성) → 정답 지식의 **지금** 컬렉션으로 묻게 고친다(이름 대신 정답 id 기준 — 재구성에 안 깨지게).

**순서(개발 때)**: 지식 축 → 질의별 진단 + 운영 숫자 → [운영 질의] 탭·[골든셋에 추가] → 표본 채점(보정 포함) → 기존 화면 이름 바꾸기는 각 단계에 같이.

## 4. 안 하는 것 + 다시 볼 조건
- 모든 질의 채점 — 비용. 표본 결과가 주마다 크게 흔들리면 표본을 늘린다.
- 실시간 경보 — 주 단위로 시작. 운영 사용량이 하루 단위로 볼 만큼 생기면.
- 자동 골든셋 추가(조건 규칙, LangSmith식) — 지금은 사람이 [골든셋에 추가]. 표본 채점이 "검색/생성"으로 판정한 질의가 주 수십 건씩 쌓이면 후보 자동 추가 검토.
- 사용자에게 별점 묻기 — "답변 틀림" 신고로 충분. 신고율이 너무 낮아 신호가 안 되면.
