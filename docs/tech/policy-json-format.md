# 정책서 표준 JSON 형식 (v1)

> 2026-10-06, v2.124. 정책서를 시스템에 넣는 표준 입력이다. 사람이 쓰는 원본은 엑셀 그대로 두고, 올릴 때만 이 JSON으로
> 바꾼다. 서버 검증 코드: `backend/service/policy/json_format.py`. 변환기: `backend/scripts/excel_to_policy_json.py`.

## 왜 JSON인가

- **사내 문서 보안(DRM)**: 암호화된 엑셀은 서버가 열 수 없다. 담당자 PC에서 JSON으로 바꿔 올린다.
- **정확도**: 엑셀 파서 출력과 1:1이라 지금의 정책 파이프라인(분해 → 파라미터 RDB + 서술 벡터 → 식별키 버전 관리)을 그대로
  탄다. MD로 바꾸면 표 병합·줄바꿈 본문이 깨지고 결국 지식 문서 경로로 가서, 파라미터 정확 조회·버전 관리가 사라진다
  (2026-10-06 실측: 정책 경로 hit@10 87.6% vs 지식 문서 경로 82.0%).
- **검증**: 오타·누락을 업로드 시점에 위치와 함께 거부한다(엑셀은 실행해 봐야 안다).

## 흐름

| 단계 | 어디서 | AI | 하는 일 |
|---|---|---|---|
| ① 변환 | 담당자 PC | 없음 | 엑셀 칸을 그대로 옮김(분류 경로·정책명·본문·비고·행 번호). 보안 문서면 Excel 프로그램으로 읽음 |
| ② 업로드·검증 | 서버 | 없음 | 형식 오류면 전체 거부(아무것도 적재 안 함) |
| ③ 같은 정책 찾기 | 서버 | 없음 | 분류 경로+정책명 → 본문 순서로 기존 정책과 연결(v2.123) |
| ④ 분해 | 서버 | **있음** | 새·바뀐 정책만 AI가 서술/파라미터/미분류로 나눔 |
| ⑤ 검토 | 서버 | 없음 | 위험도 낮음은 자동 통과, 나머지는 사람 |

구조(JSON 형식)는 고정이고 AI가 만들지 않는다. AI는 ④에서 본문을 한 번 더 쪼갤 뿐이다.

## 형식

```json
{
  "schema": "ops-navigator/policy/v1",
  "source_name": "비즈니스정책서_온라인스토어.xlsx",
  "sheets": [
    {
      "name": "온라인스토어",
      "kind": "policy",
      "rows": [
        {"row": 3, "category_path": ["주문", "취소"], "policy_name": "카드 환불",
         "body": "당일 취소는 승인취소, 익일 이후는 3~7영업일", "remark": null}
      ]
    },
    {
      "name": "용어집",
      "kind": "glossary",
      "rows": [{"row": 2, "term": "SR", "definition": "주문 시스템", "remark": null}]
    }
  ]
}
```

| 필드 | 필수 | 규칙 |
|---|---|---|
| `schema` | ✓ | `"ops-navigator/policy/v1"` 고정 |
| `source_name` | | 원본 엑셀 파일명. 있으면 출처 파일명으로 쓴다(엑셀로 올리던 걸 JSON으로 바꿔도 "파일명 변경"이 안 됨, 골든셋 파일명 매핑 유지) |
| `sheets[].name` | ✓ | 시트 이름, 파일 안에서 중복 불가. "원본에서 사라짐" 판단이 시트 이름 단위라 **바꾸지 않는다** |
| `sheets[].kind` | ✓ | `policy` 또는 `glossary` |
| `rows[].row` | ✓ | 원본 엑셀 행 번호(1 이상, 시트 안에서 중복 불가) |
| `category_path` | ✓(policy) | 문자열 배열. 대분류→소분류 순. 같은 정책인지 판단하는 키의 일부 |
| `policy_name` | ✓(policy) | 비어 있으면 안 됨. 분류 경로와 함께 식별키 |
| `body` | ✓(policy) | 문자열(빈 값 허용, 줄바꿈 그대로) |
| `term`·`definition` | ✓(glossary) | 비어 있으면 안 됨 |
| `remark` | | 문자열 또는 null |

- **키 이름은 고정**이다(위 표). JSON은 사람이 쓰지 않고 변환기가 만들기 때문에, 팀마다 다른 건 엑셀 헤더 이름이고 그건
  변환기가 흡수한다(헤더 후보 + `--map`). 서버가 키를 추측하면 식별키가 조용히 틀어질 수 있어 추측하지 않는다.
- **필수값 누락·형식 깨짐 → 파일 전체 거부**(아무것도 반영 안 함 — 일부만 들어가면 빠진 정책이 "원본에서 사라짐"으로 잘못
  표시된다). 화면에 **어디(시트 이름 + 엑셀 행 번호) / 무엇이 문제 / 이렇게 고치세요** 표로 보여 준다. 필수 키 대신 비슷한
  이름(`name` 등)이 있으면 "혹시 이것?"까지 안내.
- **모르는 키 → 경고만**(무시하고 반영, 화면 "반영은 됐지만 확인할 것"). 다른 도구로 만든 JSON이나 나중에 늘어날 필드에서
  덜 깨지게.

## 변환기 사용

```bash
python backend/scripts/excel_to_policy_json.py 비즈니스정책서_온라인스토어.xlsx          # → 같은 이름 .json
python backend/scripts/excel_to_policy_json.py 정책서.xlsx -o out.json --via-excel       # 보안 문서: Excel로 읽기
```

- 파이썬 + `openpyxl` 필요. 보안 문서를 Excel로 읽으려면 `pywin32`(Windows).
- 파일을 직접 못 열면 Excel 프로그램 방식으로 자동 전환한다. 두 방식의 결과는 같다(2026-10-06 실측).
- 시트마다 **어느 엑셀 칸을 어디로 읽었는지** 출력한다. 본문 칸을 못 찾으면 경고 — 헤더 이름이 다른 팀 템플릿은
  `--map 본문="정책 내용"`(정책명·본문·비고·용어·정의)로 지정해 다시 변환한다. 서버에 엑셀을 직접 올릴 때도 같은 정보가 결과
  화면에 나온다.
- **처음 한 번 확인**: 만든 JSON이 회사 DRM에 의해 다시 암호화되는지. 암호화되면 서버가 JSON도 못 읽는다.

올리기: 관리자 › 정책 › **정책서 올리기**(파트 선택 → 파일 → 올리기). 결과에 신규·새 버전·변경 없음·위치만 갱신·이름/분류
변경·중복 키, 원본에서 사라진 정책 수가 나온다.

## 다음 버전에서 늘릴 수 있는 것 (팀 결정 필요)

- **정책 ID**: 고정 ID 열이 생기면 식별키 1순위로(지금은 분류 경로+정책명).
- **조건 필드 분리**: 적용 대상·채널·조건·예외를 본문에서 떼어 별도 칸으로 — "~에만 적용되는 규정" 질문을 필터로 정확히
  답할 수 있다(지금 이 유형 79%, 가장 약함). 그때 `schema`를 v2로 올린다.
