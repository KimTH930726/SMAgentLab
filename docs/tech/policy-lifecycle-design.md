# 정책 추가·폐기·분류 옮기기 + 원문 확인 정리 — 설계안 (2026-10-23 밤, 검수 대기)

> 백로그 §0-5(사용자 10/23): "정책은 이 시스템이 기준 — 초기본만 문서(v0)로, 이후 추가·수정·삭제는 시스템에서. 파일 업로드는 통째로 갈아엎을 때만."
> 설계안·목업만. 구현은 검수 후.

## 1. 지금 막힌 일
- 화면에서 할 수 있는 정책 변경 = **원문·비고 수정 제안**뿐. 새 정책 추가·폐기·다른 분류로 옮기기는 길이 없어 결국 파일을 다시 올려야 한다
  → "개정본을 파일로 돌리면 관리가 안 된다"(사용자).
- 원문 확인 카드는 [해결]·[닫기]만 — 카드에서 정책을 열어 수정 제안을 올려도 카드는 그대로 "처리 전"으로 남고, 제안이 승인돼도 사람이 카드를 따로 닫아야 한다.

## 2. 업계 (조사 10/23)
- 정책 관리 도구(PowerDMS·NAVEX PolicyTech): 새 버전이 옛 버전을 대체하고 옛 것은 보관(삭제 아님), 검토·승인 흐름, 담당자에게 갱신·**폐기** 시점 알림,
  변경 이력 전부 감사 기록(powerdms.com/policy-management-software · medicine.yale.edu/myysm/policies/policytech/what-does-policytech-do — 벤더·도입처 자료).
- 우리와 같다: 이미 버전(supersedes)·승인(정정 요청)·`deprecated` 상태가 있다. 빠진 건 **변경 종류**(추가·폐기·옮기기)와 원문 확인 카드 연결뿐.

## 3. 하는 것 (MVP)
정정 요청(`ops_improvement_item`)에 정책 변경 종류 3개를 더한다 — 승인은 지금처럼 **품질 › 정정 요청 한 곳**.

| 종류 | 어디서 | 승인하면 | 되돌리기 |
|---|---|---|---|
| 정책 추가 | 분류(목차) 줄의 [이 분류에 정책 추가 제안] | 새 logical_id + 시스템 원천 키, v1 active, 검색 색인·답변 캐시 비움 | 폐기 제안 |
| 폐기 | 정책 상세 [폐기 제안](사유 필수) | 현행 → `deprecated`(지우지 않음 — 이력·골든셋이 추적), 검색에서 빠짐 | 복원 제안(같은 logical_id·키) |
| 분류 옮기기 | 정책 상세 [분류 옮기기 제안](분류 고르는 창) | 새 버전(category_path만 다름) active, 옛 버전 은퇴 | 다시 옮기기 |

- 골든셋 보호: **폐기** 승인 때 그 정책을 정답으로 쓰는 골든 문항 수를 승인 창에 보여 준다("이 정책을 정답으로 쓰는 문항 3개 — 승인하면 검색 측정에선 실패로, 답 측정에선 판정불가로 셈 · 골든 정리 필요"
  — `eval_golden_v0.py`는 현행에 없는 정답을 실패로 세고, `eval_answers`는 판정불가로 뺀다).
  옮기기는 새 버전이 원천 키(source_key)·logical_id를 그대로 이어받아 골든 정답이 유지된다(`improvement/service.py` _apply_policy) — 경고 없음.
- **새 정책의 원천 키**: 골든 정답·JSON 내려받기/가져오기가 모두 source_key로 정책을 찾는다(`json_io.py` — 키 없는 정책은 내려받기에서 빠짐).
  추가 제안 승인 때 시스템 키(`sys:<logical_id>`)를 붙인다 → 내려받기·가져오기·골든 작성에 그대로 쓰인다. 폐기 후 다시 추가는 **복원**(같은 logical_id·키로 새 버전)으로 —
  새로 만들면 이력·골든 연결이 끊긴다.
- 원문 확인 카드의 정책 칩은 현행 정책만 보여 준다(`source_check.py`) → 폐기된 정책이면 칩 대신 "폐기된 정책 #n" 표시.
- 원문 확인 정리:
  ① 카드에서 연 정책으로 제안을 올리면 카드 = **정정 요청 중 #n**(제안 번호 링크) → 제안 승인 시 카드 자동 해결(메모 = "정정 #n 승인") · 반려 시 카드가 다시 처리 전으로
  ② [닫기] → **[문제 없음]**(사유 고르기: 원문이 맞음 · 이미 고쳐짐 · 중복 · 기타 직접 입력)
  ③ (나중) 사람이 질문을 올리는 길·정기 점검 결과도 같은 수신함 — 이번엔 안 함.

## 5. 안 하는 것 + 다시 볼 조건
- 정책 직접 편집(승인 없이 바로 반영) — 사용자 10/21 결정(사람은 최종 승인만). 
- 분류(목차) 자체의 추가·이름 바꾸기·합치기 — 정책 옮기기로 대부분 해결. 빈 분류가 쌓이거나 분류 이름 바꿀 일이 2번 이상 생기면.
- 시행일·종료일(예약 반영) — 3단계 계획(policy-v0-design §7). 날짜 있는 개정이 실제로 오면.
- 일괄 변경(여러 정책 한 번에 옮기기) — **지금은 길이 없다**: JSON 가져오기는 원문·비고만 반영하고 분류·이름 바뀐 칸은 무시 목록으로만 보인다(`json_io.py`).
  한 번에 10개 넘게 옮길 일이 실제로 생기면 JSON 가져오기에 분류 칸을 여는 쪽으로(정정 요청 한 건으로 묶어 승인).

## 6. 검수 질문
1. 폐기 = `deprecated`(지우지 않음)로 충분한가?
2. 추가 제안은 분류 줄에서만(정책 상세 밖) — 맞나?
3. [문제 없음] 사유는 고르기 + 기타 직접 입력 — 고르기 목록 4개면 되나?
4. 원문 확인 카드 자동 해결 — 반려되면 카드를 다시 "처리 전"으로 되돌리는 게 맞나(아니면 "반려됨" 표시만)?
