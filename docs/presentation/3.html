  • 별도 벡터DB 클러스터 구축·운영 불필요
  • 벡터=파생물, pg=원본

  • 의미 유사도로 캐시 히트
  • 캐시 히트 시 LLM 호출 자체를 스킵 → 토큰 비용 절감 (코드로 확인됨)

★ COREDATA HUB FOUNDATION

왜 RAG 파이프라인이 핵심인가

"지식이 어떻게 데이터화되고, 어떻게 다시 찾아지는가" — 이게 데이터 허브 과제의 본체다.

  • 챗봇 = 검색결과를 보여주는 창구일 뿐
  • 실제 자산 = 등록 → 표현(청크/벡터) → 저장 → 검색 → 선순환 파이프라인 자체
  • 표준화해두면 다음 데이터(정책서/VOC/온톨로지)도 같은 골격에 편입 가능

RAG-3CHUNKING STRATEGY

청킹 전략 4종

auto
섹션 있으면 section, 없으면 paragraph — 기본값
section
문서 섹션 단위. 너무 크면 재분할, 너무 작으면 이웃과 병합
예시"## 1. 서버 재기동\n...\n## 2. 로그 확인\n..." ▸ 청크 2개(제목 단위)
paragraph
빈 줄 기준 분할. 작은 단락은 합치고, 큰 단락은 fixed로 재분할
예시회의록 3단락(빈 줄로 구분) ▸ 짧으면 1청크로 병합, 길면 분리
fixed
고정 길이 + overlap. 단어 경계에서 자름(문장 중간 절단 방지)
예시2500자 원문 ▸ 청크1(0~2000자)+청크2(1900~2500자) — 100자 겹침으로 문맥 유지
파라미터값
최소 청크 길이50자
최대 청크 길이2000자
overlap(fixed)100자
전략 자동 선택 로직실제 코드
if strategy == "auto":
    strategy = "section" if doc.sections and len(doc.sections) > 1 else "paragraph"
  • xlsx/csv 표 — 섹션에 행 데이터 이미 포함, 별도 표 청크 안 만듦
  • 본문 삽입된 표(Confluence/PDF) — 마크다운 표로 변환해 별도 청크 추가
  • 같은 "표"도 소스에 따라 처리 경로 다름

RAG-6EMBEDDING & DEDUP

배치 임베딩 + 중복 방지

① 단건 등록 — 유사도 임계값 넘으면 대기 큐로

  • 등록 직전 기존 지식과 코사인 유사도 비교, 0.88 이상이면 대기(pending_review)로 등록
  • 동시 등록 경쟁(같은 내용 2건이 동시에 들어오는 경우)은 DB 잠금 1줄로 방지 — 부가 기술 디테일이라 여기선 생략

② 대량 업로드 — 배치 내 상호 중복은 행렬곱 1회로

같은 배치 안 청크끼리는 서로 아직 DB에 없어 ①의 방식으론 못 잡음 → 임베딩끼리 한꺼번에 비교

RAG-6.5RETRIEVAL STRATEGIES

검색 전략 종류 — 뭘 언제 쓰나

전략방식이럴 때 유리우리 프로젝트
Vector코사인 유사도(HNSW)표현이 달라도 의미로 찾음rag_knowledge, policy_chunk
Keyword낱말 겹침 매칭(OR, ts_rank)특정 단어가 꼭 들어가야 할 때rag_knowledge 병행
RDB 정확조회낱말 겹침 매칭을 짧은 구조화 필드에구조화 값(코드·파라미터)policy_param, 공통코드 카테고리
Hybrid벡터+키워드 가중합기본 전략 — 대부분의 질문rag_knowledge 기본값
RerankerCrossEncoder 재정렬넓게 뽑고 정밀 재정렬구현됨, 현재 비활성
final_score = (w_vector × v_score + w_keyword × k_score) × (1 + base_weight)
  • w_vector / w_keyword 기본 0.7 / 0.3, 슬라이더로 개인화
  • top_k 기본 5, 반환 개수
  • candidate_k 리랭커 활성 시 더 넓게 뽑아 재정렬
  • Reranker는 코드로 이미 구현돼 있음(설정값 하나로 켜고 끔)
  • 현재는 비활성 — 폐쇄망 환경에 CrossEncoder 모델 번들링 전이라 꺼둠
  • 번들링 완료되면 플래그만 켜면 바로 사용 가능

측정 ② — precision@K

hit@K는 정답 유무만 이진 판정하고 후보군에 잡음(무관한 문서)이 얼마나 섞였는지는 안 본다. 같은 hit@K라도 후보 10~20개 중 진짜 정답 비율이 다르면 LLM이 헷갈릴 위험도 다르다는 뜻이라 추가했다. 그리고 B(구조분리)는 RDB+벡터를 매 질문마다 항상 같이 돌리는 구조라, "합쳐서 잘 찾는다"까진 알아도 그 안에서 실제로 뭐가 찾아내는지는 안 보여서 그 경로도 나눠 쟀다.

장기 청사진 — 운영 Agent Harness로 가는 길
