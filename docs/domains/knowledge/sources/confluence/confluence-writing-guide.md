# 컨플루언스 작성 가이드 — 운영 지식 검색이 잘 되는 페이지 쓰는 법

> **대상**: 운영 매뉴얼·시스템 정보를 컨플루언스에 쓰는 각 팀 담당자.
> **왜 필요한가**: 지식 검색 시스템(OpsLens)은 컨플루언스 페이지를 **원본 서식 그대로 읽어서** 나눈다.
> LLM이 페이지를 이해해서 정리해 주지 않는다 — 섹션을 나누는 기준은 **헤딩(제목 스타일)** 하나뿐이다.
> 같은 내용이라도 쓰는 방식에 따라 검색 정확도가 달라진다.

---

## 규칙 6가지

### 1. 섹션 제목은 반드시 "제목 1~4" 스타일로
- ✅ 편집기의 **제목 1 / 제목 2 / 제목 3** 으로 지정
- ❌ 굵은 글씨, 큰 글씨, "1. ○○" 같은 번호 문단으로만 구분
- **이유**: 시스템은 헤딩 태그로만 섹션을 나눈다. 헤딩이 없으면 페이지 전체가 한 덩어리로 취급돼, 질문과
  관련된 부분만 정확히 찾지 못하고 엉뚱한 부분이 같이 딸려 간다.
- 등록 화면에서 **"헤딩 없는 페이지 n개 — 섹션 구분 안 됨"** 경고가 뜨면 이 규칙을 안 지킨 페이지다.

### 2. 한 섹션에는 한 주제만
- 채널·서비스·대상별로 규칙이 다르면 **섹션을 나누고, 제목에 구분어를 넣는다.**
  - ✅ `배달앱A — 취소 정책` / `배달앱B — 취소 정책`
  - ❌ `취소 정책` 아래에 두 채널 내용을 섞어 쓰기
- **이유**: 실제 사례 — 두 채널 섹션의 본문이 토씨 하나 안 다르게 같았고, 어느 채널 얘기인지 구분할 정보가
  섹션 제목에만 있었다. 제목이 구분해 주지 않으면 답변에서 채널 규칙이 섞일 수 있다.

### 3. 조건·예외는 그 규칙 바로 아래에
- "단, ○○인 경우 제외" 같은 예외는 **그 규칙과 같은 섹션, 바로 다음 문단**에 쓴다.
- **"단 / 다만 / 예외 / 주의"** 로 시작하는 문단은 시스템이 앞 내용에 붙여서 함께 다룬다.
- **이유**: 예외가 멀리 떨어지거나 다른 섹션에 있으면, 규칙만 검색되고 예외는 빠진 답이 나온다
  (실제 사례: "자사몰만 적용" 조건이 분리돼 조건 없는 답이 나간 적 있음).

### 4. 상위 페이지는 "업무 단위"로
- 페이지 트리에서 **바로 위 페이지의 제목**이 그 지식의 업무 분류로 쓰인다.
- ✅ `외부서비스 > 배달앱A 연동` 처럼 상위 페이지가 업무 구분이 되게
- ❌ `잡다한 정리 > ...` 처럼 의미 없는 상위 페이지

### 5. 표만 있는 페이지는 피하기
- 표 앞에 **헤딩 + 한두 문장 설명**("아래 표는 ○○별 △△ 기준")을 둔다.
- 아주 큰 표는 주제별로 나눠 각각 헤딩을 단다.
- **이유**: 표만 있으면 섹션 구분이 없고, 큰 표가 잘리면 "이 행이 무슨 표의 행인지" 맥락이 끊긴다.

### 6. 중요한 내용은 접기·탭 매크로 밖에
- 접기(expand), 탭, 패널 같은 매크로 안의 내용은 추출이 안 될 수 있다. 핵심 절차·조건은 본문에 쓴다.

---

## 등록할 때 확인할 것

1. 지식 등록 → Confluence → 페이지 선택 → **청크 검토 화면** 상단을 본다.
2. **"헤딩 없는 페이지 n개"** 경고가 있으면 경고에 마우스를 올려 페이지 목록을 확인하고, 가능하면 원본을 고친 뒤
   다시 등록한다(같은 페이지를 다시 등록하면 옛 버전은 자동으로 교체된다).

## 근거 (2026-10-01 실측, 실제 컨플루언스 지식 51건)

- 시스템은 질문과 관련된 작은 조각을 찾은 뒤, **같은 상위 섹션의 이웃 조각을 함께** 답변 근거로 넘긴다.
  이 방식으로 여러 섹션을 함께 봐야 하는 질문의 답변 완결성이 78% → 90%로 올랐다.
- 이 개선은 **섹션이 헤딩으로 나뉘어 있을 때만** 제대로 작동한다. 당시 데이터의 33%는 헤딩 없이 작성돼
  페이지 전체가 한 단위로 묶였다.
