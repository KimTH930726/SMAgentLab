| 구분 | 기술 | 비고 |
|---|---|---|

## 스택 선택 배경 (참고)

- **PostgreSQL + pgvector 단일 DB**: 별도 벡터 전용 DB(Pinecone/Weaviate 등)를 두지 않고
  관계형 데이터와 벡터를 같은 트랜잭션 경계 안에서 다룰 수 있게 함 — namespace_id FK로
  도메인을 격리하는 이 프로젝트의 멀티테넌시 패턴과 궁합이 좋음.
  Redis는 필수 의존성이 아니라 **없어도 기능이 정상 동작**하도록 모든 캐시/레이트리밋
  경로에 graceful degradation을 넣어뒀다 — 인프라 장애 시 Redis 하나 때문에 전체가 멎지
  않게 하려는 설계.
- **임베딩 모델**: 처음 로컬(Mac) 개발 환경에서 돌려야 했던 제약으로 CPU에서도 무리 없이
  도는 다국어 모델(`paraphrase-multilingual-mpnet-base-v2`, 768차원)을 선택했다. 교체를
  대비해 스키마에 미리 준비해뒀던 `embedding_model` 컬럼(`rag_knowledge.embedding_model`,
  v2.68)이 실제로 쓰인 게 v2.72 — 89문항 골든셋 실측(hit@10 +26.9%p)으로 한국어 검색
  특화 모델 KURE-v1(1024차원)로 확정, 전체 벡터 컬럼 재색인까지 완료.
