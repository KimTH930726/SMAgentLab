# Ops-Navigator 프로젝트 개요

> 팀 기술 Confluence 공유용 문서. 코드/DB 상세는 `docs/architecture.md`·`docs/table-definition.md`·
> `docs/api-specification.md`(레포 내 `docs/`, 변경 시마다 동기화되는 1차 소스)를 참고. 이 문서는
> 그 내용을 팀 소개용으로 재구성한 요약본이다.

## 한 줄 정의

**Ops-Navigator**는 IT 운영팀의 반복적인 조회·확인 업무를 지식 기반 AI 채팅으로 자동화하는
**지능형 운영 보조 에이전트 플랫폼**이다. 사내에 흩어진 운영 노하우(지식 문서), 정책서(비즈니스
규정), 이메일 민원(VOC)을 하나의 검색·응답 파이프라인으로 묶는다.

## 왜 만들었나

IT 운영팀은 "이거 어떻게 처리하지?", "이 정책 조건이 뭐였지?" 같은 반복 질문에 매번 사람이
문서를 뒤지거나 선임에게 물어봐야 했다. 이 과정을 다음 세 축으로 자동화한다.

1. **지식 Q&A**: 운영 담당자의 노하우/해결방안을 등록해두면, 유사한 질문이 들어왔을 때 AI가
   검색해서 답한다.
2. **정책서 조회**: 엑셀로 관리되던 비즈니스 정책서(재고/주문/클레임 등)를 구조화해 자연어로
   질의할 수 있게 한다.
3. **VOC(민원) 자동 분석**: 팀 메일함으로 들어오는 이메일을 자동 분류·분석하고, 반복되는
   유형을 감지해 담당자에게 알린다.

## 팀/조직 컨텍스트

- **소속**: AIOps 팀. 팀의 핵심 목표는 "비즈니스 정책서를 포함한 운영 데이터를 데이터화해
  활용할 수 있는 구조를 만드는 것" — Ops-Navigator는 그 **공통 데이터 허브의 한 축**이다.
- **협업 범위**: 정책서 데이터화는 CSP팀(스타벅스 온라인스토어/딜리버스)의 실 정책서를
  기반으로 검증했다.
- **최종 착지점**: 지금은 이 레포에서 프로토타이핑하고 있지만, 최종적으로는 **팀 공통
  포털의 백엔드 모듈로 이관**하는 것이 목표다. 그래서 SMAgentLab 전용 인프라(자체 인증·배포)에
  과투자하지 않고, 처음부터 포털에 얹을 수 있도록 `/api/` 경계를 깨끗하게 유지하는 설계
  원칙을 따른다.

## 현재 범위 (v2.68 기준)

| 영역 | 상태 |
|---|---|
| **KnowledgeRAG 채팅 에이전트** | 운영 중 — 하이브리드 검색(벡터+키워드), 대화 메모리, 피드백 루프 |
| **정책서 데이터화 파이프라인** | 운영 중 — 온라인스토어(398건)+딜리버스(102건) 실 데이터 적재, 채팅에 편입 완료 |
| **VOC 이메일 분석 채널** | 운영 중 — Microsoft Graph API 연동, 반복 패턴 탐지, Teams 알림 |
| **지식 생명주기 관리** | 초기 단계 — 중복탐지/병합이력/소프트삭제/피드백 리뷰 큐 |
| **팀 SSO(Azure AD) 연동** | 착수 — 스키마 선반영, 앱 등록 승인 대기 |
| **Text-to-SQL 에이전트** | 제거됨(현재 과업 아님) — `archive/with-text2sql` 브랜치에 보존 |
| **MCP 도구 에이전트** | 완전 제거됨 — 미사용 기능 정리 |

## 규모 감

- 지식 베이스(`rag_knowledge`): 약 3,000여 건
- 정책 항목(`policy_item`): 480건(온라인스토어 378 + 딜리버스 102), 파라미터 389건/서술
  청크 다수
- 정책서 검색 정답률 평가(골든셋 89건, 실 DB 기반 자동 생성): 하이브리드 스키마가 4개
  질문 유형 전부에서 우세, 전체 정답률 57.3% → 75.3%로 개선(벡터 폴백 도입 후)

## 문서 안내

이 폴더(`docs/confluence/`)의 나머지 문서:

- `01-아키텍처.md` — 시스템 구성, 컴포넌트, DB, 배포 구조
- `02-흐름도.md` — 핵심 처리 흐름(채팅 검색, VOC 파이프라인, 정책서 파이프라인 등)
- `03-기술스택.md` — 사용 기술/라이브러리와 선택 이유
- `04-기능설명.md` — 기능별 상세 설명

더 깊은 기술 상세(전체 변경 이력, DB 컬럼 단위 정의, API 요청/응답 스펙)는 레포 `docs/`
루트의 `architecture.md`/`table-definition.md`/`api-specification.md`를 참고한다 — 이 문서들은
기능이 바뀔 때마다 코드와 함께 갱신되는 1차 소스이고, 여기 confluence 문서들은 그 스냅샷
요약이다.
