# 기능 설명

> 각 기능의 목적, 동작 방식, 관련 코드 위치를 정리했다. 상세 API 스펙은
> `docs/api-specification.md`, DB 컬럼은 `docs/table-definition.md` 참고.

## 1. KnowledgeRAG 채팅 에이전트

**목적**: 운영 담당자가 등록해둔 지식(노하우/해결방안)과 정책서 데이터를 자연어 질문으로
검색·응답.

**핵심 동작**
- **하이브리드 검색**: 벡터(의미 유사도) + 키워드(정확 매칭) 점수를 가중합해 랭킹
  (`agents/knowledge_rag/knowledge/retrieval.py`). 사용자가 사이드바 슬라이더로 벡터/키워드
  비중과 Top-K를 실시간 조정 가능.
- **용어집(Glossary) 매핑**: 사내 은어("쿠폰 뺏어오기")를 표준 용어("회수")로 매핑해 검색
  정확도를 높인다. 유사도 0.5 이상일 때만 매핑 적용.
- **카테고리 기반 라우팅**: `DB`/`공통코드`처럼 구조화된 코드표 카테고리는 벡터 검색을
  끄고 키워드 검색만 사용한다(코사인 유사도가 구조화 데이터에서 어휘만 겹쳐도 오탐을
  내는 것이 실측으로 확인됨, v2.49).
- **대화 메모리**: 4회 교환마다 LLM이 요약해 벡터로 저장(ConversationSummaryBuffer +
  Semantic Recall) — 오래된 대화는 요약으로, 최근 2회는 원문 그대로 LLM에 전달.
- **멀티턴 검색 보강**: 직전 질문+답변을 현재 질문에 결합해 검색 — "그거 알려줘" 같은
  짧은 후속 질문도 맥락을 반영해 검색된다.
- **Few-shot 예시**: 과거 긍정 피드백을 받은 Q&A 쌍을 프롬프트 앞부분에 예시로 포함.
- **정책 근거 카드**: 정책서 데이터가 있는 네임스페이스에서는 답변 근거가 된 정책 원문을
  별도 카드로 노출(§흐름도 문서 참고).
- **Semantic Cache**: 코사인 유사도 0.97 이상인 과거 질문이면 재계산 없이 캐시된 답변을
  즉시 반환(Redis, TTL 30분, agent_type별로 분리돼 서로 다른 에이전트 캐시가 섞이지 않음).

## 2. 지식 베이스 관리 (Admin)

**목적**: 지식 등록/수정/삭제와 품질 관리를 관리자 화면에서 수행.

**핵심 동작**
- **등록 경로 다양화**: 파일 업로드(txt/md/pdf), 대량 텍스트 붙여넣기, 직접 입력,
  URL/Confluence 수집(BFS 일괄), Teams 메시지 수집.
- **자동 파이프라인**: 업로드된 문서는 파싱(`adapters.py`) → 청킹(`chunker.py`,
  section/paragraph/fixed/auto 전략) → LLM 분석(`analyzer.py`, 문서 유형/청킹 전략 자동
  결정) → 자동 태깅(`tagger.py`) → Q&A 자동 생성(`qa_gen.py`, few-shot 후보로 등록) 순서로
  처리된다.
- **중복 탐지**: 등록 시점에 청크 단위로 기존 활성 지식과 유사도 비교(임계치 0.88 기본).
  임계값 이상이면 `pending_review` 상태로 저장하고 검색에서 숨긴다. 관리자가 승인/반려/
  병합 중 선택 — 병합 시 기존 내용은 `rag_knowledge_history`에 먼저 보존한다(v2.68).
- **소프트 삭제**: 삭제해도 DB에서 완전히 지워지지 않고 `status='deleted'`로만 바뀐다(v2.68,
  실수 삭제 복구 가능).
- **리뷰 신호 큐**: 나빠요 피드백이 달린 답변이 실제로 근거로 삼은 지식 전체를 리뷰
  후보로 쌓는다(자동 감점 아님, 사람이 확인하는 큐). 관리자 화면 "리뷰 신호" 탭에서 확인.
- **대량 업로드 진행률**: 백그라운드 작업(job_id 폴링)으로 처리, 중지 시 등록분 롤백 지원.

## 3. 정책서 데이터화 파이프라인

**목적**: 엑셀로 관리되던 비즈니스 정책서(재고/주문/클레임 등 규정)를 구조화해 자연어로
질의 가능하게 만든다.

**핵심 동작**
- **3층 분해**: 정책 한 row를 `policy_item`(원문+메타) / `policy_param`(파라미터 팩트) /
  `policy_chunk`(서술 청크)로 LLM이 분해해 적재. 팀마다 다른 대/중/소분류 깊이는
  `category_path TEXT[]`로 흡수(고정 컬럼 대신 가변 배열).
- **하이브리드 검색**: 파라미터는 RDB 정확조회(tsquery), 서술은 벡터 검색 — 이 방식이
  지식-only 저장 방식보다 나은지 골든셋 89건으로 실측 검증했고(§4 저장소 실험실), 4개
  질문 유형 전부에서 우세함을 확인한 뒤 채팅에 편입했다.
- **버전 관리**: 재업로드 시 UPDATE로 덮어쓰지 않고 새 row를 INSERT(logical_id 유지,
  version+1, supersedes_id로 이전 버전 연결, 이전 row는 deprecated로 보존) — 지식 베이스
  병합이 이력 없이 덮어썼던 문제(§4 지식 생명주기)를 반복하지 않도록 설계.
- **미해결(unresolved) 캡처**: LLM이 서술/파라미터 어느 쪽으로도 자동 분류하지 못한 내용은
  원문 그대로 보존하고 사유를 기록한다(데이터 유실 없음). 완전 자동화 대신 "자동 처리
  비율 최대화 + 실패 사유 캡처"가 목표.
- **관리자 화면**: 항목 브라우저(전체 훑어보기), 미분류 리포트(팀별 집계), 저장소 실험실
  (A/B 정답률 비교 재실행) 3개 서브탭.

## 4. VOC 이메일 분석 채널

**목적**: 팀 공용 메일함으로 들어오는 민원(VOC)을 자동 분류·분석하고, 반복 유형을 감지해
담당자에게 알린다.

**핵심 동작**
- **수집**: Microsoft Graph API로 파트별 공용 메일함을 백그라운드 폴링(스케줄러).
- **관련지식 사전 필터**: 등록된 지식과 무관한 메일(스팸/사내공지)은 LLM 호출 없이
  스킵 — 비용·알림 노이즈 절감.
- **분석**: 기존 하이브리드 검색 파이프라인을 재사용해 분류/심각도(4단계)/오배치 여부를
  판정. 프롬프트에 넣기 직전 개인정보(IP/이메일/전화번호)를 마스킹(DB/알림엔 원본 유지) —
  사내 LLM 게이트웨이가 민감정보 포함 프롬프트를 거부하는 정책 때문에 추가.
- **반복 패턴 탐지**: 이미 계산된 임베딩을 재사용해 과거 VOC와 비교(pgvector 코사인
  연산만, LLM 호출 없음). 7일 내 3건 이상 유사 건이 쌓이면 반복 패턴으로 확정.
- **해결방안 커버리지 판정**: 반복 패턴에 대해 등록된 지식이 있는지 코사인 1차 필터 +
  LLM 재검증으로 판정(순수 유사도만으로는 무관 문서가 CS 보일러플레이트 문구만으로
  오탐되는 것이 실측 확인됨).
- **Teams 알림**: 담당 파트 채널로 발송, 반복 패턴이면 카드에 "🔁 반복 패턴 — N건째 발생"
  표시. 30일 보관정책으로 오래된 분석 이력 자동 정리.
- **관리자 화면**: 인증(로그인)/라우팅(파트별 메일함 매핑)/폴링 설정 3단계 + 분석 이력 +
  VOC 통계(유형/심각도 분포, 반복 클러스터 목록, 클러스터에서 바로 지식 등록) + 분석·알림
  테스트.

## 5. 인증/인가 및 팀 SSO

**핵심 동작**
- JWT 기반(Access 30분 + Refresh 7일), 네임스페이스 소유 파트 기반 권한(같은 부서만
  CRUD, 공통 네임스페이스는 전 부서 CRUD).
- 사용자별 LLM API Key/Confluence PAT를 Fernet 대칭암호화로 저장.
- **팀 SSO(Azure AD) 착수 현황**: `ops_user`에 `auth_provider`/`external_id`/`email` 컬럼을
  선반영(로컬 계정이 소수인 지금이 스키마 확장 비용이 가장 싼 시점이라는 판단). 실제
  OIDC 로그인 흐름은 Azure AD 앱 등록 승인 이후 구현 예정.
- 로그인 브루트포스 방어(Redis rate limit, 5분 내 5회 실패 시 5분 잠금), 계정 열거
  오라클 제거(존재하지 않는 아이디와 비밀번호 오류를 구분하지 않는 통합 에러 메시지).

## 6. 지식 생명주기 관리

**목적**: 지식 베이스가 커질수록 발생하는 중복/이력소실/삭제복구불가 문제를 관리.

**진행 현황** (`docs/tech/knowledge-lifecycle-design.md` 참고)
- 병합 이력 보존, 소프트 삭제, 향후 버전관리를 위한 스키마 선추가(`logical_document_id`/
  `version`/`supersedes_id`/`embedding_model`/`quality_score`/`reviewed_at`/`owner`),
  피드백→지식 리뷰 신호 큐까지 완료.
- LLM 기반 지식 품질 자동 평가(LLM Comparator)는 실측 근거(중복탐지 발동 이력이 초기
  대량 반입 시점에만 몰려있고 이후 거의 재발동하지 않음)로 현재는 우선순위를 낮춰둔 상태 —
  등록 볼륨이 실제로 늘어나면 재검토.
