> 슬라이드 수: 1장
> 목표: 이 시스템이 가져오는 변화와 가까운 다음 단계를 간결하게 전달한다

---

## [슬라이드 6-1] 기대효과와 다음 단계

### 제목
**이 시스템이 가져오는 변화, 그리고 다음**

### 본문 내용

**지금 달라지는 것**

- 질문 → 시스템 즉시 답변
- 흩어진 지식 → 검색 가능한 조직 자산
- 몰랐던 공백 → 가시화 + 채움
- 반복 문의·숙련자 부재 → **온보딩 비용 절감**
- 메일은 와 있어도 사람이 열어봐야 비로소 인지되던 VOC → **도착과 동시에 시스템이 선제 감지**해 자동 분류·심각도 판정·담당 파트 Teams 알림(개인 계정 기준 전체 플로우 시연 완료)

**이미 검증 완료 — VOC 메일링**
- 기존 VOC 시스템의 키워드 규칙으로 파트별 메일함에 전달된 메일을 폴링 → 관련지식 필터 → RAG 분석 → 라우팅 → Teams 알림까지 전체 파이프라인 구현·시연 완료(기존 필터링 위에 지능형 분석·선제 알림 레이어를 얹은 구조)
- 남은 건 기술이 아니라 **조직 승인**뿐 — Microsoft 365 보안성 검토 진행 중, 승인 즉시 부서 공용 메일함으로 확대 적용 가능
- **실 운영 효능**: "사람이 발견"에서 "시스템이 선제 감지"로 전환 · 긴급 건은 사람이 인지하기 전에 온콜 담당자 자동 멘션 · 무관한 메일(스팸·공지)은 LLM 호출 전에 걸러 비용·알림 피로도 방지 · 오배치 메일 자동 감지
- **한계도 명확히**: 상류 VOC 시스템의 키워드 규칙에 걸려 메일함까지 온 것만 감지 대상 — 전수 커버는 아니며, 등록된 지식이 없는 완전히 새로운 유형의 이슈는 분석 품질이 낮을 수 있음(슬라이드 3 상세 참고)

**데이터가 쌓이면 열리는 것**
- 운영 매뉴얼 자동화 — 반복 Q&A 기반으로 초안 생성 제안 → 사람이 검토·등록
- MCP 확장 — 장애·배포 이력, 모니터링 알림 등 운영 시스템과 결합한 답변으로 확장

**가까운 다음 단계**

| 카테고리 | 항목 | 기대효과 |
|----------|------|---------|
| **VOC 메일링 정식 전환** | Application 권한 승인(조직 승인 진행 중) → 부서 공용 메일함 확대 | 개인 검증에서 전사 무인 운영으로 전환, 별도 개발 없이 설정만으로 확대 |
| **VOC 시스템 직접 연계** (장기, 미착수) | 이메일이라는 중간 경유지 없이 VOC 시스템과 API로 직접 연동 | 상류 키워드 규칙에 의존하지 않는 전수 감지로 커버리지 개선 |
| **지식 현행화** | 폴링 기반 변경감지(우선) + 사내 Confluence가 Webhook 지원 시 전환(`knowledge-refresh-automation-plan.md`) | 문서 수정 시 자동 재수집 → 수동 재등록 부담 제거 |
| **통합 알림 채널 확장** | 관제 알림 등 추가 채널 연동 | VOC 메일링과 동일한 구조(수집→필터→분석→라우팅)를 재사용해 확장 |

### 발표자 노트
> "결국 이 시스템이 만드는 변화는 단순합니다 — 질문하면 바로 답이 나오고, 지식은 사람이 아니라 조직에 쌓이고, 몰랐던 공백은 눈에 보여서 채울 수 있게 됩니다. 그 결과가 온보딩 비용 절감으로 이어집니다.
> 그리고 오늘 중점적으로 보여드린 VOC 메일링은 이제 '구상'이 아니라 '완성된 기능'입니다. 개인 계정 기준으로 수집부터 Teams 알림까지 전체 흐름을 이미 검증했고, 남은 건 조직의 보안 승인뿐입니다. 승인이 나는 순간 코드 변경 없이 설정만으로 전체 부서로 확대됩니다. 다만 지금은 상류 VOC 시스템의 키워드 규칙에 걸린 것만 저희가 감지할 수 있다는 한계는 있고, 그래서 다음 단계 중 하나로 VOC 시스템과의 직접 연계도 로드맵에 넣어뒀습니다.
> 가까운 다음 단계도 이 연장선입니다 — 지식이 outdated 되지 않게 자동으로 현행화하는 것, 그리고 VOC 메일링에서 검증한 같은 구조(수집→필터→분석→라우팅)를 다른 알림 채널로도 넓히는 것. 둘 다 이미 갖춰진 인프라 위에서 설정 수준으로 빠르게 실현할 수 있습니다."
